## High‑Level Architecture

- **Backend (Node.js / Express)** – located under `BACKEND/`.
  - **API entry point**: `src/app.js` sets up the Express server, middleware stack, and mounts route modules.
  - **Routes**: Files in `src/routes/` expose REST endpoints for authentication, trips, notifications, etc.
  - **Services**: Business logic lives in `src/services/` (e.g., `emailService.js`, `amadeusService.js`, `weatherService.js`).
  - **Data models**: Mongoose schemas are defined in `src/models/` (`User.js`, `Trip.js`). Unique constraints are preferred over manual indexing.
  - **Configuration**: `src/config/env.js` loads environment variables; `API_BASE_URL` can be overridden via a `.env` file.

- **Frontend (React + Vite)** – located under `FRONTEND/`.
  - **Entry point**: `src/main.jsx` mounts the React app and sets up React Router.
  - **Context layer**: `src/context/` provides `AuthContext.jsx` (authentication state) and other cross‑cutting concerns.
  - **API abstraction**: `src/services/api.js` wraps `fetch` calls, handling tokens and error conversion, exposing `authApi`, `tripsApi`, `notificationApi`.
  - **State management**: `src/store.js` uses Redux Toolkit with RTK Query for data fetching/caching; slices are under `src/slices/`.
  - **Routing**: `src/App.jsx` defines protected routes via `ProtectedRoute.jsx` which relies on the authentication context.
  - **Feature components**: Located in `src/components/` and grouped by concerns (`features/`, `ui/`).
  - **Pages**: Top‑level routes like `HomePage.jsx`, `LoginPage.jsx` live in `src/pages/`.
  - **Styling/UI primitives**: Reusable UI components (e.g., `Button.jsx`, `ErrorBanner.jsx`, `GlassCard.jsx`) reside in `src/components/ui/`.

- **Shared utilities** – helper functions such as date formatters are placed in `src/utils/`.

- **Testing** – backend tests use Jest; frontend tests use Vitest with React Testing Library. Test files are co‑located with the modules they cover (`*.test.js` or `*.test.jsx`).

- **Environment variables** – frontend variables are prefixed with `VITE_` and accessed via `import.meta.env`. Authentication tokens are stored under `TOKEN_KEY` in `localStorage`/`sessionStorage` and cleared on 401 responses.

- **CI/CD** – a typical GitHub Actions workflow (not shown) runs lint, tests, and builds on every push.
